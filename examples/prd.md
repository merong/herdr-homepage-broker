# Example Studio 홈페이지 · Higgsfield 이미지 생성 테스트 PRD

## 목표와 범위
가상의 회사 Example Studio를 소개하는 한국어 반응형 랜딩 페이지를 만든다.
히어로, 서비스 3개, 회사 소개, 데모 문의 영역을 포함한다. 회사 실적·고객·주소는 지어내지 않는다.
산출물은 app/ 소스와 localhost 미리보기이며, 사용자 검토 대기에서 마친다.
배포·결제·분석 추적·폼 서버는 제외한다. PM·개발자·디자이너의 3개 역할만 사용한다.

## 필수 이미지 생성 시나리오
이번 테스트 실행에서 디자이너가 설치된 Higgsfield MCP의 이미지 생성 도구를 실제 호출하여 새로운 히어로 이미지 1장을 만든다.
이미지 생성은 선택 사항이 아니다. 기존 hero.jpg 재사용, 스톡 이미지, SVG/CSS 대체물은 이 테스트의 통과 조건을 충족하지 않는다.
생성 요청은 count=1로 1건만 제출한다. 생성 모델은 설치된 홈페이지 스킬과 도구에서 지원하는 모델을 선택해 기록한다.
디자이너는 접속 가능한 Higgsfield 도구를 확인하고 생성 시작·job 접수·완료 시 간결한 progress 보고를 남긴다.
연결·인증 실패는 실제 오류를 포함한 입력 요청 1건으로 알린다. 결과 불명확 또는 실패 시 추가 유료 제출하지 않고 확인을 요청한다.

## 작업 순서
1. PM은 고정 팀을 생성하고 이미지 생성 → 개발자 통합 → 최소 검토의 의존성을 계획한다.
2. 디자이너는 design.md의 프롬프트로 1장을 생성하고 실행 폴더 assets/에 원본·웹용 이미지와 media-receipts.json을 저장한다.
3. 개발자는 전달받은 새 이미지를 app/assets/에 복사하여 실제 히어로 img 요소에 사용한다. 이미지가 완료되기 전 최종 납품하지 않는다.
4. PM은 생성 기록과 이미지 연결, localhost 응답을 한 번 확인한 후 사용자 검토로 넘긴다. 반복적인 디자인 QA는 하지 않는다.

## 최소 통과 증거
- media-receipts.json에 provider, tool, model, prompt, count, 제출 시각, 실제 provider_job_id, 완료 상태, 결과 URL, 로컬 경로 및 SHA-256을 기록한다. 추측한 job ID나 완료 상태를 쓰지 않는다.
- 개발자 완료 보고에 적용한 app/assets/ 경로와 SHA-256을 포함하여 디자이너가 제공한 웹용 파일과 일치시킨다.
- localhost에서 히어로 이미지가 표시됨을 한 번 확인하고 이미지 HTTP 응답 및 실제 크기(naturalWidth > 0)를 확인한다.
- 신규 생성 여부·job ID·이미지 경로·미리보기 URL을 최종 보고에 남긴다. CSS로 장식한 것만으로 생성 완료라 하지 않는다.
