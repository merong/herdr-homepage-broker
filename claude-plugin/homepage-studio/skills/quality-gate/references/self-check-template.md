# reports/self-check.md 작성법

check 태스크에서 1–4절을 쓰고, close 태스크에서 5–8절을 덧붙인다. 앞 절은 close에서 고치지 않는다. 판정은 `통과`, `실패`, `해당 없음`, `확인 못 함` 가운데 하나다. 근거 없는 `통과`는 쓰지 않는다. 확인하지 못한 항목은 통과로 쓰지 않고 `확인 못 함`으로 쓴다.

## 템플릿

```markdown
# 자가 점검: <브랜드명>

- run_id: <run_id>
- 점검 시각: <ISO 8601>
- 미리보기: http://127.0.0.1:<port>/ (출력 디렉터리 <절대 경로>)
- 자동 검사: reports/auto-check/auto-check.json — issue_count <n>
  (생략된 경우: "자동 검사 생략: <skipped 값>. 대체: 첫 화면 스크린샷과 수동 점검. 확인 못 한 항목은 표에 표시")
- 읽은 슬라이스: desktop-00…<nn>, mobile-sheet-0…<n>

## 1. 한눈 판정

- 차단 <n>개, 중요 <n>개, 경미 <n>개
- 가장 큰 문제 세 가지 (한 줄씩)
- 이 사이트에서 기억에 남는 한 가지 (B5)
- 고객이 스크린샷만 보고 받을 첫인상 (두 문장 이내)

## 2. 항목별 판정

| ID | 판정 | 심각도 | 근거 |
| --- | --- | --- | --- |
| A1 | 통과 | 차단 | viewports.*.navigation_error 없음 |
| A5 | 실패 | 차단 | mobile overflow 412px > 390px, `.process-table` (desktop-03, mobile-sheet-1) |
| D2 | 실패 | 차단 | "누적 1,200건" — copy-deck에 F# 없음, research에 없음 |
| … | | | |

(A1–J8 전부. 근거에는 JSON 키, 파일과 줄, 슬라이스 이름, 명령 출력 요약을 쓴다.)

## 3. 수정 목록 (fix 태스크의 유일한 입력)

| # | ID | 심각도 | 위치 | 현상 | 바꿀 내용 | 확인 방법 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | D2 | 차단 | `app/src/sections/proof.html` 14행 | 출처 없는 수치 | 문장 삭제. 리드를 아래 최종 문구로 바꾼다 | grep "1,200" 결과 없음 |
| 2 | D6 | 차단 | 푸터 | COPY-GAP: 운영 시간 | 최종 문구: "평일 9시–18시, 토요일은 예약 상담만 받습니다." | grep COPY-GAP 결과 없음 |
| … | | | | | | |

규칙:
- 차단을 모두 넣고 중요를 영향이 큰 순서로 넣는다. 합쳐서 10개 이내다.
- 문구를 바꾸는 항목은 최종 문구를 따옴표 안에 그대로 쓴다. 줄바꿈 의도는 ` / `로 표시한다.
- 색, 크기, 간격은 정확한 값(토큰 이름이나 hex, px, em)으로 쓴다.
- 새 이미지 생성, 새 섹션, 디자인 방향 변경은 넣지 않는다.
```

## 쓰는 요령

- 표의 근거는 다른 사람이 같은 파일을 열어 같은 결론에 이를 수 있을 만큼만 쓴다. 긴 명령 출력을 붙이지 않는다.
- 같은 원인에서 나온 실패는 한 수정 항목으로 묶는다(예: 같은 토큰을 쓰는 글자 대비 실패 세 곳).
- 위 예시의 파일 이름, 문구, 수치는 형식 예시다. 실제 run의 값으로 바꾼다.
