# reports/design-brief.md 작성법

frontend-design의 방법을 따른다. 먼저 토큰 계획을 세우고, 기본값처럼 보이는 부분을 찾아 고친 뒤에 구현한다. 이 문서가 디자인의 원본이다. 개발자와 디자이너는 이 문서와 다르게 만들지 않는다.

## 레이아웃 패밀리 어휘

섹션 계획은 아래 이름으로 적는다. **인접한 두 섹션은 같은 패밀리를 쓸 수 없다.** 한 페이지에서 같은 패밀리는 최대 2번이다. `grid`는 1번까지다.

| 패밀리 | 설명 | 주의 |
| --- | --- | --- |
| `split` | 텍스트와 이미지를 좌우로 나눈 비대칭 구성(5:7, 4:8 등) | 6:6 반복 금지 |
| `full-bleed` | 전폭 이미지나 영상 위에 텍스트 | 대비 확보, 텍스트는 이미지의 빈 영역에 |
| `statement` | 큰 문장 하나와 넓은 여백 | 문장이 약하면 쓰지 않는다 |
| `index-list` | 행 단위 목록(제목, 설명, 메타가 한 줄씩) | 번호는 실제 순서가 있을 때만 |
| `grid` | 타일과 카드 그리드 | 같은 모양의 카드 3장 반복 금지. 크기나 비율에 위계를 둔다 |
| `mosaic` | 크기가 다른 이미지 콜라주 | 이미지 3장 이상 필요 |
| `sequence` | 단계와 타임라인 | 내용이 실제 순서일 때만 |
| `proof` | 출처 있는 인용, 인증, 지표 | 사실 ID가 없으면 섹션 자체를 만들지 않는다 |
| `spec` | 표, 사양, 가격 | 표 형식이 맞는 내용일 때만 |
| `sticky` | 한쪽은 고정되고 다른 쪽이 스크롤된다 | 모바일에서는 일반 흐름으로 바꾼다 |
| `contact` | 연락처, 지도 정보, 문의 폼 | 지도 임베드는 외부 의존이므로 주소 텍스트와 길찾기 링크로 대신한다 |

## 한국 기업 사이트의 기본값 목록 (기본값 점검용)

frontend-design의 AI 경향 5가지, Higgsfield `reference-boards.md`의 팔레트 금지 목록과 함께 아래도 점검한다. 업종과 브리프가 요구하지 않는데 들어가 있으면 기본값이다.

1. 남색에서 하늘색으로 가는 그라데이션 히어로와 지구본, 네트워크 선, 도시 야경 이미지("글로벌 기업" 클리셰)
2. 악수, 노트북을 가리키는 사람, 전구, 퍼즐 조각, 홀로그램 같은 스톡 상징 이미지
3. 회사소개서 순서: 대표 인사말 → 연혁 → 조직도 → 사업 분야 → 오시는 길
4. '핵심 가치' 아이콘 카드 3장(신뢰·혁신·상생 등)
5. 숫자 카운터 애니메이션("누적 고객 ○○명")
6. 회색 배경, 파란 버튼, 둥근 모서리 카드 일색
7. 자동으로 넘어가는 히어로 슬라이더(캐러셀)
8. 모든 섹션 제목 위의 영문 대문자 라벨(OUR SERVICE, ABOUT US)
9. 섹션마다 똑같이 반복되는 fade-up 등장 효과

## 템플릿

```markdown
# 디자인 브리프: <브랜드명>

## 0. 요약
- 이 사이트가 할 일 한 가지:
- 독자(구체적인 한 사람과 상황):
- 고객이 스크린샷에서 3초 안에 느껴야 할 것:
- 업종의 재료와 말(디자인 근거가 될 사물, 공정, 장소, 업계 용어):

## 1. 팔레트 (4–6색)
| 이름 | hex | 역할 | 근거 |
| --- | --- | --- | --- |
대비 쌍: 본문 텍스트/배경 ○:1, 버튼 텍스트/버튼 ○:1 (본문 4.5:1, 큰 글자와 UI 3:1 이상)

## 2. 타입
| 역할 | 폰트(한글 / 라틴) | 웨이트 | 크기(데스크톱/모바일) | 행간 | 자간 |
| --- | --- | --- | --- | --- | --- |
| 디스플레이 h1 | | | | | |
| 제목 h2 | | | | | |
| 본문 | | | | | |
| 캡션·라벨 | | | | | |
선택 이유(korean-typography 참조), 정렬 원칙(왼쪽 정렬 기본, 가운데 정렬은 어디에만):

## 3. 레이아웃 컨셉
한 문장 컨셉 + 후보 2개의 ASCII 와이어프레임 비교 → 선택과 이유.

    +--------------------------------------------------+
    | 로고                          메뉴 메뉴 [CTA]    |
    |                                                  |
    |  헤드라인 두 줄            [  히어로 영상/이미지 ]|
    |  서브카피                  [                    ]|
    |  [주 CTA] 보조 링크        [                    ]|
    +--------------------------------------------------+

모바일(390px) 와이어프레임도 히어로와 가장 복잡한 섹션 하나는 그린다.

## 4. 원칙 (3–5개)
이 페이지만의 규칙. "대담함은 한 곳에": 그 한 곳이 어디이고 무엇인지 적는다.

## 5. 기본값 점검
같은 업종의 다른 회사 브리프를 받았다고 가정하고, 1분 안에 떠오르는 기본안을 먼저 적는다. 내 계획과 겹치는 축을 표시하고 고친다.
| 축 | 처음 계획 | 기본값처럼 보이는 이유 | 수정한 계획 |
| --- | --- | --- | --- |
점검 범위: frontend-design AI 경향 5가지 / 팔레트 금지 / 위 '한국 기업 사이트 기본값 목록'

## 6. 섹션 계획
| # | 섹션 | 할 일 하나 | 레이아웃 패밀리 | 에셋 슬롯 | CTA |
| --- | --- | --- | --- | --- | --- |
| S1 | 히어로 | | full-bleed | hero-video, hero-still | 주 CTA |
(인접 섹션 패밀리 중복 없음, 같은 패밀리 최대 2회)

## 7. 에셋 계획
asset-kit의 배분표 형식으로 슬롯, 수량, 비율, 크롭을 적는다. 공통 스타일 블록 원문도 여기 적는다.

## 8. CTA 목록
| ID | 라벨(정확한 문구) | 무엇이 일어나나 | 위치 | 주/보조 |
| --- | --- | --- | --- | --- |

## 9. 모션
페이지 로드 연출이나 하나의 등장 효과만 쓴다. reduced-motion 대체 방식도 적는다.

## 10. 가정
| 가정 | 근거 | 틀렸을 때 고칠 곳 |
| --- | --- | --- |
(고객에게 묻지 않고 추론한 판단. 로고 마크를 생성했다면 "시안"이라고 적는다.)
```
