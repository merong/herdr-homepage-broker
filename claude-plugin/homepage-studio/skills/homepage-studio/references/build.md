# 빌드 규칙 (build·fix 태스크, homepage-developer)

입력은 `reports/design-brief.md`, `reports/copy-deck.md`, `assets/`(특히 `assets/web/`와 `assets/media-receipts.json`)다. 출력은 `app/`이다. 브리프와 카피덱에 없는 것은 만들지 않는다.

## 스택과 출력

- 스택은 자유다. 단, 출력은 정적 파일(HTML, CSS, JS, 미디어)이어야 하고 `python3 -m http.server`만으로 동작해야 한다. SSR, 서버 함수, API 라우트를 쓰지 않는다.
- 주요 콘텐츠는 초기 HTML에 들어 있어야 한다. JS가 그려 넣는 본문은 쓰지 않는다. 가벼운 선택지는 순수 HTML/CSS와 소량의 JS, Vite 정적 빌드, Astro 정적 출력이다.
- 출력 디렉터리(예: `app/dist/`)는 처음 정한 경로를 유지한다. 루트 `/`에서 서빙된다고 가정하되, base 경로는 설정 한 곳에 모아 README에 적는다.
- **실행 중 외부 요청 0.** 폰트, 스크립트, 아이콘, 이미지, 지도를 모두 로컬에 둔다. 자동 검사의 `external_hosts`가 비어 있어야 한다. 분석 도구와 채팅 위젯은 넣지 않는다(납품 후 고객이 넣는다).
- PM에게 빌드 명령과 미리보기 argv를 정확히 넘긴다. 예:
  `["python3","-m","http.server","{port}","--bind","127.0.0.1","--directory","<절대경로>/app/dist"]`

## 브리프와 카피덱을 그대로 옮긴다

- 브리프 §1·§2를 CSS 사용자 정의 속성(`--color-*`, `--font-*`, `--step-*`)으로 옮긴다. hex와 수치를 바꾸지 않는다.
- 섹션 순서와 레이아웃 패밀리는 브리프 §6을 따른다. 패밀리마다 마크업과 그리드를 다르게 만든다. 같은 컴포넌트에 내용만 바꿔 끼우지 않는다.
- 브리프 §6의 섹션 하나는 `<main>` 안의 최상위 `<section>` 하나이고, `data-section="S3"`처럼 S# 번호를 단다. 자동 검사가 최상위 `<section>`으로 섹션 수와 레이아웃 반복을 센다.
- 문구는 카피덱 원문 그대로 쓴다. 줄바꿈 위치도 카피덱 표기를 따른다(korean-typography '줄바꿈'). 빠진 문구는 `<!-- COPY-GAP: … -->`로 표시하고 PM에게 알린다.
- CTA 라벨과 위치는 브리프 §8을 따른다. 같은 행동에는 어디서든 같은 라벨을 쓴다. 버튼은 브리프에 맞춰 직접 디자인한다. 기본 파란 알약 버튼, 라벨 끝 `→`는 쓰지 않는다.
- 타이포는 korean-typography, head 태그·파비콘·sitemap·JSON-LD는 seo-basics, 이미지·영상 마크업은 asset-kit '웹 반영'을 따른다.
- 접근성과 성능은 처음부터 quality-gate `references/checklist.md`의 G·H 항목에 맞춰 만든다. 나중에 고치는 것보다 싸다.

## 모션

- 브리프 §9의 한 순간만 만든다. 섹션마다 fade-up을 넣지 않고, 모든 카드에 hover 들림 효과를 넣지 않는다.
- `@media (prefers-reduced-motion: reduce)`에서는 이동과 자동 재생을 멈춘다.
- 스크린샷이 판정 기준이다. 등장 애니메이션 때문에 정지 화면에서 요소가 투명하거나 화면 밖에 남아 있으면 안 된다. 초기 상태가 보이는 상태가 되도록 만든다.

## 문의 폼

- 필드와 문구는 카피덱 §폼을 따른다. `<label>`을 연결하고 `required`, `autocomplete`(`name`, `email`, `tel`, `organization`), `inputmode="tel"`을 쓴다. 입력 글자 크기는 16px 이상이다.
- 오류는 필드 아래에 `aria-describedby`로 연결한다. 제출에 실패하면 첫 오류 필드로 포커스를 옮긴다.
- 개인정보 수집·이용 동의 체크박스와 짧은 고지(수집 항목, 목적, 보유 기간)를 둔다. 보유 기간은 회사가 정할 값이므로 카피덱의 자리표시 문구를 쓰고 README '공개 전 필수'에 올린다.
- 스팸 방지는 숨긴 honeypot 필드로 한다. 외부 CAPTCHA는 쓰지 않는다.
- 전송은 `submitInquiry(data)` 함수 하나로 분리한다. 화면 상태는 이 함수의 결과로만 정한다.
- **성공 문구는 실제 전송이 확인됐을 때만 보여 준다.** 설정된 엔드포인트(`<form data-endpoint="…">`)가 2xx를 돌려준 경우뿐이다. 엔드포인트가 비어 있거나, 요청이 실패하거나, 응답이 2xx가 아니거나, honeypot이 채워졌으면 "받았습니다", "접수되었습니다", "전송되었습니다" 같은 문구를 쓰지 않는다. 그렇지 않으면 납품 후 실제 고객 문의가 소리 없이 사라진다.
- 엔드포인트가 있으면 JSON으로 POST한다. 2xx면 카피덱 §4 '성공' 문구를 보여 주고 폼을 비운다. 그 밖에는 '실패' 문구와 아래 표의 연락 수단을 보여 주고 입력값을 그대로 둔다.
- 엔드포인트가 비어 있으면(납품 기본값) 검증한 뒤 카피덱 §4 '엔드포인트 없음'의 방식 하나를 따른다. 방식은 research.md의 연락 사실로 정해진다.

| research.md의 연락 사실 | 동작 | 화면 |
| --- | --- | --- |
| 출처 있는 이메일(사실 ID) | `mailto:` 넘기기. 받는 주소는 그 이메일이다. 제목과 본문은 카피덱의 틀에 필드 값을 채우고 `encodeURIComponent`로 인코딩한다 | 메일 앱이 열린다는 안내만 한다. 보냈다고 말하지 않는다. 메일 앱이 없는 환경을 위해 주소를 글자와 링크로 함께 보여 준다. 입력값은 지우지 않는다 |
| 이메일은 없고 전화 등 다른 연락 사실이 있음 | 보내지 않는다 | 출처 있는 전화(`tel:` 링크)와 다른 채널을 안내한다 |
| 연락 사실이 없음 | 검증만 하고 보내지 않는다 | 문의 창구를 준비하고 있다는 중립 안내를 한다. PM에게 알리고 README '공개 전 필수' 맨 위에 적는다. quality-gate는 이것을 차단 항목(I3)으로 '남은 문제'에 올린다 |

```js
// 엔드포인트가 없고 출처 있는 이메일이 있을 때. 제목·본문 틀과 라벨은 카피덱 §4에서 가져온다
const subject = `[홈페이지 문의] ${data.organization || data.name}`;
const body = [`이름: ${data.name}`, `연락처: ${data.tel}`, `이메일: ${data.email}`, "", data.message].join("\r\n");
location.href = `mailto:${CONTACT_EMAIL}?subject=${encodeURIComponent(subject)}&body=${encodeURIComponent(body)}`;
```

- `CONTACT_EMAIL`은 `SITE_URL`과 같은 설정 한 곳에 둔다. 아주 긴 `mailto:` 주소는 일부 메일 앱에서 잘릴 수 있으므로 메시지 필드에 `maxlength`를 두고, 그 값을 카피덱 도움말과 맞춘다.
- check에서 PM이 이 분기를 코드로 읽는다. 빌드 출력이 축약되어 읽기 어렵다면 PM은 `app/`의 소스를 읽는다.

## app/README.md (한국어)

1. 개요: 스택, 설치·빌드 명령, 출력 디렉터리, 로컬 미리보기 명령
2. **공개 전 필수**
   - `SITE_URL` 교체: canonical, og:url, og:image, sitemap, robots, JSON-LD
   - 문의 폼 연결: 연결 전에는 폼이 문의를 서버로 보내지 않는다는 사실과 현재 방식(메일 넘기기, 연락처 안내, 중립 안내 가운데 하나)
   - 개인정보 보유 기간 확정
   - 로고가 시안인지 여부
   - 검색엔진 소유 확인 메타(Google Search Console, 네이버 서치어드바이저)
3. 문의 폼 연결 방법
   - `data-endpoint`를 지정하는 위치
   - 요청 형식(필드 이름과 JSON 예시)
   - 2xx일 때만 성공 문구를 보여 주는 분기와 실패 처리의 위치
   - 엔드포인트가 다른 도메인이면 CORS 설정이 필요하다는 점
   - 폼 백엔드 서비스나 자체 API 같은 선택지
   - 연결한 뒤 실제로 한 건을 보내 받는지 확인하는 방법
4. 자산 출처: AI 생성 이미지·영상 목록(Higgsfield, job id는 run의 `assets/media-receipts.json`), 고객 제공 자산, 폰트와 라이선스 파일 위치
5. 고치는 법: 문구 위치, 색·폰트 토큰 위치, 폰트 서브셋 재생성 명령(쓴 경우)
