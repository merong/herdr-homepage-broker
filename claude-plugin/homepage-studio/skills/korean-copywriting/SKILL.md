# 한국어 카피라이팅

기준은 하나다. **경쟁사가 로고만 바꿔 달고 그대로 쓸 수 없는 문장인가.** (로고 바꿔치기 테스트)

- 산출물: `reports/copy-deck.md`. 형식은 references/copy-deck-template.md를 따른다.
- 개발자는 이 문서의 문구만 쓴다. 마이크로카피(내비게이션, 폼, 오류, 푸터, alt, 메타)까지 이 문서에서 끝낸다.
- 기법은 references/craft-ko.md, 금지 패턴은 references/ai-tells-ko.md에 있다.
- 패스 구조와 진단·셀프에딧 방식은 copy-that-sells(MIT, Tato Polanco)를 한국어 맥락에 맞게 고쳐 쓴 것이다. 출처는 `THIRD_PARTY_NOTICES.md`에 있다.

## 패스 순서 (건너뛰지 않는다)

### 0. 브리핑

research.md와 design-brief.md에서 다음 8가지를 한 줄씩 뽑는다. 빠진 것은 추론해서 '가정'으로 표시한다. 고객에게 묻지 않는다.

1. 이 페이지가 할 일 하나 (예: 금형 견적 요청을 받는다)
2. 독자: 인구통계가 아니라 특정 상황에 있는 한 사람 (예: "라인 증설을 앞두고 협력사를 찾는 생산기술 과장")
3. 독자가 지금 믿는 것과 바꿔야 할 믿음
4. 약속: 구체적인 이득 하나
5. 증거: research.md의 사실 ID 목록. 증거가 없는 약속은 쓰지 않는다
6. 형식 제약: 히어로는 5초, 모바일 첫 화면 390×844
7. 어조: 합니다체 또는 해요체, 회사를 가리키는 말
8. CTA: 읽고 나서 할 행동

### 1. 앵글

- 명제를 한 문장으로 쓴다. 그 명제에 대한 서로 다른 아이디어를 3–7개 쓴다(각 한 문장). 그중 하나를 고른다. 버린 아이디어도 한 줄씩 남긴다.
- 포스터 테스트: 헤드라인 한 줄과 이미지 한 장만으로 아이디어가 전달되는가.
- research.md '경쟁사 공통 표현'으로 시작하는 아이디어는 버린다. '비어 있는 자리'에서 출발한 아이디어를 우선한다.

### 2. 헤드라인

- 후보를 8개 이상, 4가지 이상의 유형으로 쓴다(유형은 craft-ko.md).
- 4U로 채점한다: 쓸모, 시의, 고유, 구체. 3개 이상이 강해야 통과한다.
- 로고 바꿔치기 테스트: 경쟁사 3곳의 이름을 넣고 읽는다. 그대로 말이 되면 탈락이다.
- 헤드라인과 히어로 이미지는 한 단위다. 이미지가 보여주는 것을 헤드라인이 다시 말하지 않는다.

### 3. 섹션 카피

- design-brief.md 섹션 계획 순서대로 쓴다. 섹션마다 할 일은 하나다.
- 형용사 자리에 사실을 넣는다. "꼼꼼한 검수"가 아니라 무엇을, 몇 번, 누가 하는지 쓴다. 수치는 사실 ID가 있을 때만 쓴다.
- 증거가 없는 섹션은 만들지 않는다. 후기, 고객사 로고, 수상, 수치 카운터는 출처가 있을 때만 둔다.
- 본문은 독자가 묻는 순서를 따른다: 무엇을 하나 → 나에게 뭐가 좋은가 → 믿을 근거 → 어떻게 진행되나 → 어떻게 연락하나. 회사소개서 순서(인사말 → 연혁 → 조직도)를 기본으로 쓰지 않는다.

### 4. 셀프에딧 (세 층)

1. **크래프트**: 소리 내어 읽는다. 한 호흡에 읽히는지, 문장 길이를 섞었는지 본다. 형용사와 접속어를 지운다.
2. **AI 티**: ai-tells-ko.md의 8가지 유형을 전부 훑는다. 고치기 전→후를 3건 이상 카피덱 부록에 남긴다.
3. **사실**: 모든 수치, 고유명사, 연도에 사실 ID가 있어야 한다. 없으면 지우거나 검증 가능한 구체(과정, 재료, 장소, 방식)로 바꾼다.

## 길이 기준 (공백 포함 글자 수)

| 요소 | 권장 | 상한 | 비고 |
| --- | --- | --- | --- |
| 히어로 헤드라인 | 12–22자 | 28자 | 데스크톱 2줄, 모바일 3줄 이내 |
| 히어로 서브카피 | 40–80자 | 100자 | 1–2문장 |
| 섹션 제목 | 8–20자 | 26자 | 한 줄이 기본 |
| 섹션 리드 | 30–60자 | 80자 | 제목 아래 한 문장 |
| 본문 문단 | 80–160자 | 220자 | 2–3문장 |
| 카드·항목 제목 | 4–12자 | 16자 | |
| 카드 설명 | 30–70자 | 90자 | |
| CTA 버튼 | 4–10자 | 12자 | 동사로 끝낸다 |
| 버튼 아래 마이크로카피 | 15–35자 | 40자 | 한 줄 |
| 메타 title·description | seo-basics | | |

상한을 넘으면 내용을 줄이거나 문장을 나눈다. 글자 크기를 줄여서 맞추지 않는다.

## 문체: 합니다체와 해요체

| 사이트 | 기본 문체 | 예 |
| --- | --- | --- |
| B2B, 제조, 건설, 금융, 법률·회계, 의료기관, 공공 | 합니다체 | "도면을 받은 다음 날 견적을 드립니다." |
| 소비자 대상 로컬 서비스, 생활 브랜드, 교육, 앱 | 해요체 가능 | "방문 전에 사진으로 먼저 봐 드려요." |

- 한 페이지의 본문은 한 문체로 통일한다. 폼 안내와 오류 문구도 같은 문체로 쓴다.
- 헤드라인, 버튼, 라벨은 명사형이나 종결을 생략한 형태를 쓸 수 있다("견적 요청하기"). 본문에 반말(해체, 한다체)은 쓰지 않는다.
- 회사를 가리키는 말은 브랜드명과 "저희" 중 하나로 정해 통일한다. "당사"는 법적 고지에만 쓴다. "고객님"과 "여러분"을 남발하지 않는다. 한국어에서는 2인칭을 생략하는 편이 자연스럽다.
- 과잉 공손은 쓰지 않는다("~해 드리고 있습니다", "~하실 수 있으십니다").

## 실제 회사 규칙

- **이름**: 법인명은 등기·공시 표기 그대로 쓴다. "주식회사"의 앞뒤 위치, "(주)" 약칭, 영문 대소문자와 띄어쓰기까지 research.md '표기 기준'을 따른다. 푸터, 개인정보 고지, JSON-LD `legalName`에는 법인명을, 본문에는 브랜드명을 쓴다.
- **지어내지 않는다**: 설립연도, 업력, 직원 수, 매출, 실적 수치, 고객사, 협력사 로고, 인증, 특허, 수상, 언론 보도, 후기, 대표 인용을 출처 없이 쓰지 않는다. "업계 1위", "국내 최초", "유일한" 같은 최상급도 출처가 없으면 쓰지 않는다.
- **추적**: copy-deck에서 사실을 담은 문장 끝에 `〔F3〕`처럼 사실 ID를 붙인다. 화면 문구에는 붙이지 않는다. self-check가 이 표시로 대조한다.
- **빈자리**: 근거가 없으면 그 섹션이나 문장을 뺀다. 그럴듯한 문장으로 메우지 않는다. 뺀 것은 카피덱 '생략' 절에 적는다.
- 경쟁사의 이름, 수치, 후기를 비교에 쓰지 않는다.
- 의료, 건강, 금융, 교육 업종은 효과 보장, 이용자 후기, 전후 비교를 쓰지 않는다. 업종 광고 규제 위험이 크다.
- 사실이 적을 때는 검증 가능한 구체로 쓴다: 공정 순서, 쓰는 재료와 장비, 일하는 장소, 담당 방식, 결정 기준, 소요 시간(출처 있음).

## CTA 명명

- 라벨은 누르면 일어나는 일을 말한다: "견적 요청하기", "방문 상담 예약", "시공 사례 보기". "제출", "확인", "클릭", "바로가기"는 쓰지 않는다. "자세히 보기"와 "더 알아보기"는 주 CTA로 쓰지 않는다.
- 행동 하나에 이름 하나다. 헤더, 히어로, 푸터, 폼 버튼, 성공 메시지가 같은 말을 쓴다(라벨 "견적 요청하기" → 성공 메시지 "견적 요청을 받았습니다"). 어휘는 design-brief의 CTA 목록에 고정한다.
- 폼의 성공 메시지는 실제 전송이 확인됐을 때만 나온다. 엔드포인트가 없는 납품 기본 상태의 문구(메일 앱 넘기기, 연락처 안내, 중립 안내)는 references/copy-deck-template.md §4를 따른다. 이 문구들은 보냈다거나 받았다고 말하지 않는다.
- 주 CTA는 한 페이지에 하나다. 보조 CTA는 부담이 더 낮은 행동이어야 한다(예: 주 "견적 요청하기", 보조 "시공 사례 보기").
- 미러 테스트: 헤드라인을 읽고 곧바로 CTA를 읽는다. 다음 문장처럼 이어져야 한다.
- 버튼 아래 마이크로카피는 한 줄로, 마지막 망설임을 줄이는 사실만 쓴다(예: "상담은 무료입니다", "영업일 기준 하루 안에 답합니다"). 사실 ID가 있을 때만 쓴다.

## 이미 있는 카피를 고칠 때

quality-gate의 수정 목록이나 기존 사이트 문구를 다룰 때는 새로 쓰기 전에 진단한다. craft-ko.md의 '진단 5문'을 순서대로 묻고, 처음 실패한 곳을 고친다. 개입 수준(고치기, 재구성, 새로 쓰기)을 정하고 그 이유를 기록한다.
